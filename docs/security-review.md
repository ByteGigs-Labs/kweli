# Security review

This is the security pass from the roadmap. Each control is listed with where it lives and the test that proves it. The tests run in CI on every push, alongside `pip-audit`, `npm audit`, gitleaks and CodeQL.

| Area | Control | Where | Proved by |
|---|---|---|---|
| Sessions | Random token in an httpOnly, `SameSite=Strict` cookie (`Secure` in production), stored only as a SHA-256 hash, 12-hour expiry. Argon2 password hashes | `api/security.py`, `api/routes/auth.py` | `test_auth.py`, `test_hardening.py::test_the_session_cookie_is_http_only_and_strict` |
| Login abuse | Per-IP rate limit, and the account locks after 5 failures in 15 minutes. The message is the same for an unknown email or a wrong password | `api/ratelimit.py` | `test_auth.py` |
| Cross-site requests | `SameSite=Strict`, CORS limited to explicit origins (no wildcard with credentials), and an **Origin check** that refuses any POST, PUT, PATCH or DELETE from another site | `api/hardening.py`, `api/config.py` | `test_hardening.py::test_cross_site_writes_are_refused` |
| Headers | API: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, a restrictive Permissions-Policy, and HSTS in production. Web: a strict CSP (`script-src 'self'`, no inline scripts, `frame-ancestors 'none'`) | `api/hardening.py`, `render.yaml` | `test_hardening.py` |
| Attack surface | The OpenAPI and docs pages are off unless `API_DOCS=true` | `api/main.py` | `test_hardening.py::test_api_docs_are_off_unless_asked_for` |
| Request size | JSON bodies are capped at 64 KB and uploads at 10 MB, both declared and streamed | `api/limits.py` | `test_documents.py` |
| Rate limits | Login, client portal, assistant (20 a minute), uploads (30 a minute), packs (5 a minute), disputes (10 a minute) and billing (6 a minute) | `api/ratelimit.py` and each route | `test_hardening.py::test_uploads_are_rate_limited`, `test_agent.py` |
| Uploads | File type sniffed from the bytes (executables refused), filenames made safe, AES-256-GCM with a key per file bound to the document ID, downloads through 5-minute HMAC-signed links | `vault/` | `test_documents.py` |
| Webhooks | PayPal verifies the signature (body passed back byte for byte), events are deduplicated by ID, and **every fact is re-read from PayPal's API** rather than taken from the webhook body | `paypal/webhooks.py`, `api/services/*` | `test_webhooks.py`, `test_disputes.py`, `test_billing.py` |
| Prompt injection | Client text reaches the AI only as data, with an "ignore instructions" note. AI output is constrained to a forced tool (extraction), validated (agent proposals take IDs only), or citation- and amount-checked (cover letter, dispute response). The client's dispute messages never reach the model | `agent/`, `api/services/extract.py`, `packs/citations.py`, `defender/response.py` | `test_agent.py`, `test_extract.py`, `test_packs.py`, `test_disputes.py` |
| Money and submissions | Nothing that sends an invoice or submits dispute evidence happens without a single-use, short-lived approval token. Tokens are stored only as hashes and never reach the model, and a dispute approval is bound to a hash of exactly what will be sent | `agent/actions.py`, `api/services/disputes.py` | `test_agent.py`, `test_disputes.py` |
| Billing | The browser never says who is Pro. Kweli reads the subscription from PayPal and checks the plan ID and the `custom_id` (the user it was created for), and a subscription can't be claimed by a second account. Checkout only redirects to an `https` `paypal.com` address. No PayPal JavaScript runs on Kweli's pages | `api/services/billing.py`, `web/src/pages/Billing.tsx` | `test_billing.py`, `Billing.test.tsx` |
| Integrity | A hash-chained audit log for each user. Compliance Packs and dispute evidence check every vault file against its stored SHA-256, and a pack refuses to build if the chain fails verification | `audit/log.py`, `packs/render.py`, `defender/files.py` | `test_audit.py`, `test_packs.py` |
| Secrets | Only in Render environment variables (`sync: false`) or generated by Render. gitleaks runs in CI. Logs record paths, never query strings or bodies | `render.yaml`, `.gitleaks.toml`, `api/logging_config.py` | CI `secrets` job, `test_logging.py` |
| Dependencies | Pinned. `pip-audit` runs on the installed environment, and `npm audit --audit-level=high` too. fpdf2 was moved to 2.8.9 after `pip-audit` flagged two CVEs in 2.8.7 | `requirements*.txt`, `web/package-lock.json` | CI `backend` and `web` jobs |

## Known gaps
- **No self sign-up.** Accounts are created by the seed script, so there is no email verification or password reset flow yet.
- **Rate limits are kept in Postgres.** They're fine for one instance. With several instances they still hold, because the store is shared, but they add a write per limited request.
- **No live load testing.** The free Render plan sleeps when idle, so the API moves to a paid instance before judging.
- **Third-party payer confirmations** are accepted as an uploaded file. Kweli checks the file's type and hash, not who signed it.
